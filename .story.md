# Video & Blog: The Story

## The Thesis

**"The bitter lesson in agentic AI: models eat frameworks."**

The interesting shift isn't "subagents" (old) or even "human-authored workflows" (L3/LangChain). It's **agent-authored workflows** (L4) — where the model writes the orchestration itself.

---

## The Narrative Arc

### 1. HOOK - The Problem Everyone's Solving

> "Everyone's building multi-agent systems. Most of them are secretly a mess."

Pain points:
- Sub-agents pollute main context
- Results are inconsistent
- Parallelism requires manual orchestration
- You end up writing more framework than code

### 2. THE TURN - Where Orchestration Lives

> "The interesting question isn't 'can agents use other agents?' 
>  It's **where the orchestration logic lives**."

The stack:
```
L1: Single agent loop          → think → tool → observe
L2: Subagents                  → you write the loop
L3: Human-authored workflows   → LangChain/LangGraph (you write the loop)
L4: Agent-authored workflows   → Agent writes the loop ✨
```

The stack (before dynamic workflows):
```
Subagents: You spawn workers, they report back, you coordinate
Agent Teams: Multiple agents coordinate, but still limited to 3-5
```

The stack (with dynamic workflows):
```
Dynamic Workflows: Agent writes the orchestration script itself ✨
Scale: 16 concurrent, 1,000 total
```

### The Key Insight from Community

> "Instead of Claude holding the plan in its context window, it writes a JavaScript orchestration script. That script becomes the plan. The orchestration logic moves from the LLM's memory into executable code."

### Why This Changes the Game

1. **Scale** - Up to 16 concurrent, 1,000 total per workflow
2. **Adversarial Verification** - Agents tackle from independent angles, others refute findings, iterate until convergence
3. **Resumability** - Progress saves continuously, interrupted jobs pick up where they left off
4. **Zero Orchestration Burden** - You describe the goal, agent decides how to split work

### 3. THE DEMONSTRATION - Side by Side

Show the comparison:
- **Without Workflows (L2/L3)**: You write 25+ lines, sequential, manual
- **With Workflows (L4)**: You write 2 lines (the objective), agent writes the loop

### 4. THE TECHNICAL STORY - Why It Works

1. **Context Isolation** - Script holds state, not main context
2. **Native Parallelism** - `map_agents()` instead of manual loops
3. **Verification Loops** - Cross-check before synthesizing
4. **Resumability** - Checkpointing for long runs

### 5. THE DEEPER INSIGHT - The Bitter Lesson

> "First, we wrote the loop. 
>  Then we wrote the workflow. 
>  Now the model writes both."

The progression:
```
Year 1: "We need to orchestrate agents!" → You write the loop
Year 2: "We need reusable workflows!" → LangChain/LangGraph
Year 3: "We need dynamic workflows!" → Agent writes the orchestration
Year N: "Why are we writing frameworks at all?" → Model writes everything
```

### 6. PREEMPTING CRITICISMS

**Q: "Isn't this just another framework?"**
A: "No, it's removing the framework. The workflow tool is minimal — it just lets the model write code."

**Q: "What about LangChain/LangGraph?"**
A: "That's L3 (human-authored workflows). We're showing L4 (agent-authored). Same family, different layer."

**Q: "What survives?"**
A: "Only the parts models can't write: runtime infrastructure, safety guardrails, tool definitions."

**Q: "What about infinite loops / token limits?"**
A: "Same concerns exist in any orchestration system. The pattern is sound; production deployment requires guardrails."

2. **What doesn't this replace?**

   - Humans define goals, not plans
   - Frameworks become runtime plumbing
